1Background

This design sits at the intersection of two prior systems, one external and one our own, and is shaped by a hard empirical result that constrains what we are allowed to claim. To read the rest of the document you need three things in hand: what SkillOpt is and the one assumption it never relaxes; what datafetch is and the bet it places; and the empirical arc that tells us which value regime survives. We close with the problem statement that the learning layer exists to solve.

Key facts (load-bearing)

  • SkillOpt (Microsoft, arXiv:2605.23904) trains a prose skill.md as the external state of a frozen agent, using a tight deep-learning analogy: parameter = skill.md, gradient = a trajectory-derived reflection edit, learning-rate = a bounded edit budget L_t (cosine 4→2), validation = a held-out selection gate that accepts iff the candidate strictly improves, rejected-edit buffer = in-epoch negative memory, momentum = an epoch-wise slow/meta update. Splits are D_tr / D_sel / D_test.
  • SkillOpt's one limitation: every one of its five evaluators is a deterministic per-task gold comparison (SearchQA SQuAD-EM, DocVQA ANLS, LiveMath MCQ, OfficeQA EM/F1, SpreadsheetBench cell-diff). It assumes a per-task oracle, and it optimizes prose the agent READS — the artifact is never executed, so its validation signal is the model re-reading its own prose (circular, oracle-bound).
  • datafetch is a substrate where a frozen agent writes typed df.* code over a mounted dataset; every primitive call is captured as structured trajectory lineage; an observer crystallises reusable typed df.lib.* helpers the agent later INVOKES (progressive disclosure via apropos / man / df.d.ts). Its bet: code is a learnable interface.
  • The falsification that reframes everything: SkillCraft proved skill-based learning works (94.4% / 172× / R7 = 0.846). But the cost-amortisation thesis was FALSIFIED on shallow fan-outs — a valid k=5 PokeAPI paired run showed (commit 0665d5a27) warm crystallised helpers cost more in every token unit AND were less correct than inline re-derivation; a quality-only gate would have promoted the losers. The surviving value regime is serial-DEPTH governance (the dark-store family showed +13.5pp).

1. SkillOpt: a text-space optimizer with one fixed assumption

SkillOpt's contribution is to treat a natural-language skill document as the trainable external state of a frozen agent and to optimize it as if it were a neural network's parameters. The frozen agent is never fine-tuned; instead, a prose skill.md is updated step by step, and SkillOpt makes the deep-learning analogy explicit and complete:

DL conceptSkillOpt instantiation
Parameterthe prose skill.md (one document, one scalar objective)
Gradient / edita trajectory-derived reflection edit (JSON patch of English rules)
Learning ratea bounded edit budget L_t, cosine-scheduled 4→2
Validationa held-out selection gate: accept iff cand_score > current strictly
Negative memorya rejected-edit buffer, rendered back into the optimizer prompt within the epoch
Momentuman epoch-wise slow / meta update

Its splits are D_tr / D_sel / D_test, and its deployment companion (SkillOpt-Sleep) already runs the offline harvest→replay→consolidate→gate→stage loop we might otherwise have reinvented. SkillOpt's ablations are worth internalising: gains are largely insensitive to batch size and schedule, but collapse without the gate and the slow update. That discipline is real and transferable.

But SkillOpt has exactly one assumption it never relaxes, and it is the assumption this design must reach past. Every SkillOpt benchmark hands the optimizer a deterministic per-task gold comparison — SQuAD-EM, ANLS, MCQ, EM/F1, cell-diff — and SkillOpt simply aggregates that oracle over a held-out split. It never builds a verifier; it assumes one. And the object it optimizes is prose the agent reads: the artifact has no execution semantics, so "validation" reduces to the frozen model re-reading its own English and re-attempting the task. That validation signal is circular and oracle-bound by construction.

2. datafetch: code as a learnable interface

datafetch starts from a different object. The agent is still frozen, but it does not read a prose skill — it writes typed df.* code over a mounted dataset and returns an answer (return await df.lib.someIntent(...)). Every primitive df.* call is captured as structured trajectory lineage: typed I/O, scope and depth nesting, replay-executable bodies. An observer mines recurring shapes from that lineage and crystallises them into typed, callable df.lib.* helpers, content-addressed by shape and intent, which the frozen agent later discovers through progressive disclosure (apropos / man / df.d.ts) and INVOKES rather than reads.

The substrate's bet is that code is a learnable interface — that the right external state for a frozen agent over data is not a prose tip-sheet but a growing library of typed callables. This single substitution (read→invoke, prose→typed code) is what makes datafetch a system delta rather than a reskin of SkillOpt-Sleep, and the difference is sharpest precisely at the place SkillOpt is weakest: a typed callable can be validated by executing it — re-run the helper on promoted literals and assert answerEquals against the agent's own prior committed answer — producing a deterministic, model-independent, oracle-free signal that prose categorically cannot generate (plan 014 §1–2). Where SkillOpt has one parameter and one scalar objective, a library is combinatorial: which helpers exist, where their boundaries fall, and crucially when to retrieve-and-reuse versus synthesize fresh. That governance frontier has no analog in SkillOpt-Sleep.

3. The empirical arc that constrains the design

Three results, in order, fix the value regime the learning layer is allowed to chase.

SkillCraft (positive). Skill-based learning over this substrate works: 94.4% pass, 172× reuse, R7 transfer = 0.846. Crystallised helpers can fire, persist, and lower per-episode work. The mechanism is sound.

The falsification constraint

PokeAPI k=5. On shallow fan-outs, the cost-amortisation thesis is FALSIFIED. In a valid, paired k=5 run, warm crystallised helpers came out more expensive in every token unit AND less correct than inline re-derivation against a frontier baseline (plan 014 §1). The sharp consequence: a quality-only gate would have promoted those losers. SkillOpt's own gate — Δquality > 0, blind to cost — is exactly such a gate. The forensic detail matters downstream: the cost gap was a turn-count tax, and the only lever that moved cost materially (~3.5×) was helper DEPTH, not width.

Dark-store family (the surviving regime). On serial-DEPTH corpora, a governed helper that declines under detected drift can strictly beat an ungoverned clone that confidently returns a stale-sibling wrong answer (the +13.5pp depth signal under a tri-state grader). This — governance-under-staleness on deep, serial-dependency tasks — is the only regime where the value claim is reachable, and the headline is therefore moved off cost-amortisation and onto a cost-aware, executed, oracle-free promotion gate whose job is to correctly reject confidently-wrong or more-expensive helpers and promote only the equally-correct-cheaper ones (plan 014 §1, §4).

4. The problem this design solves

We want a learning layer for the datafetch substrate that is as disciplined as SkillOpt but reaches the parts SkillOpt structurally could not. SkillOpt gives us a control half worth inheriting verbatim — the held-out gate, the bounded edit budget, the rejected-edit memory, and the fast/slow split — and the empirical arc tells us that this control half is exactly what stops a learned artifact from drifting into confidently-wrong reuse. We do not relitigate it; we lock it as an invariant shared by both forks (plan 015 §0–1) and never re-tune it.

The novelty budget is spent on the three things SkillOpt assumed away:

  1. Executed, oracle-free verification. SkillOpt assumes a per-task gold oracle. We cannot. We need a verifier that promotes from deterministic execution (replay-equality, drift-gated abstention, anecdotal oracle-free checks plus a computed process-reward stack that scores the procedure, not just the answer) rather than from the model judging its own output.
  2. Compositional, cost-aware acceptance. SkillOpt's gate sees a single monolith and accepts on Δquality > 0. Ours must subtract a fully-instrumented lifetime cost (build, per-call discovery and invocation turns, staleness risk, minus inline saved) and, where the object composes, optimize global compositional cost / description-length from the first commit — something SkillOpt's gate cannot see because its artifact does not compose (plan 015 §4).
  3. A structured object, and the optimizer that object demands. The headline rule: object class picks the optimizer. Prose takes reflection; a program takes induction. Running reflection on a typed call-graph is editing a program with a prose tool, and it bottoms out at thin shims by construction. The two forks (014 CodeOpt = a flat helper set under LLM reflection; 015 Procedure-Grammar Induction = a compositional typed grammar under structured anti-unify→MDL-select→gate induction) differ only in synthesis and object, over the one locked control half.
Problem statement

Given a frozen agent whose external state is a library of typed, invocable df.lib.* helpers crystallised from trajectory lineage — and given that no per-task oracle is available and that naive cost-amortisation has been empirically falsified on shallow fan-outs — design a learning layer that inherits SkillOpt's control discipline unchanged, and adds (a) an executed, oracle-free, cost-aware promotion gate that rejects confidently-wrong or more-expensive helpers and promotes only equally-correct-cheaper ones, and (b) a synthesis half matched to the object class, such that the system delivers measurable governance-under-staleness correctness on serial-depth corpora.

2Product Vision

The core claim: a data interface that distils instead of accumulating

datafetch ships a per-tenant interface to a dataset that gets structurally simpler and cheaper to use the more it is used. A frozen agent writes typed df.* code over a mounted dataset; every primitive call is captured as structured trajectory lineage; and a synthesis layer turns recurring intent into a compositional, typed procedure grammar the agent later invokes by name. The product is not the agent and not the dataset. It is the grammar in the middle, and the disciplined optimizer that keeps it honest. The grammar is the bet under pre-registered test (the R-vs-C bake-off behind the depth floor); if structured induction does not separate from flat reflection on a depth corpus, the shipped object is the flat 014 library and we say so.

The thing being sold is a negative space as much as a positive one. The default outcome of "let a model accumulate helpers" is a growing pile of thin shims that a frontier model bypasses, because reflecting over a typed call-graph is editing a program with a prose tool and bottoms out at shims by construction (plan 015, headline rule; plan 014 §2 honesty note: invoke-vs-read is cosmetic everywhere except the gate). datafetch makes the opposite commitment. Plan 015 §6 states it exactly: "SkillOpt stays small by rejecting (passive: don't grow). 015 stays small by compressing (active: shrink)." The interface anti-unifies same-intent trajectory clusters into parameterized procedures, MDL-selects only the abstractions that shorten the whole corpus, and raises lower procedures into higher ones, so the library's description length per intent falls as coverage rises. Distillation, not accumulation, is the product category.

We are honest about the regime where this can pay. Our own valid k=5 PokeAPI run falsified cost-amortisation on shallow fan-outs: warm crystallised helpers came out more expensive in every token unit and less correct than inline re-derivation, and a quality-only gate would have promoted those losers (plan 014 §1 reframe, anchor commit 0665d5a27). So the value regime is explicitly serial-DEPTH corpora, where a top-level procedure that composes several learned sub-procedures is genuinely expensive to inline, which is the only place the cost gate clears (plan 015 §2; the dark-store family's +13.5pp depth signal). We do not promise amortisation everywhere. We promise distillation where depth exists, and correct refusal to promote where it does not.

"Improves the more you use it" is a measurement, not a hope

The claim is instrumented, not asserted. Plan 015 §6 defines three distillation curves that are the product's primary telemetry:

CurveDirection if the interface is distillingWhat flat means
Description-length-per-intent↓ fallingthe grammar is not compressing
Compositional depth (mean nesting / serial-dependency length of accepted procedures)↑ risingprocedures are not composing, only listing
Inline-rederivation rate (fraction of episodes the agent re-derives instead of calling a procedure)↓ recedingthe agent is bypassing the library

The honesty clause is part of the product, not a caveat hidden from it. Plan 015 §6 is unambiguous: "if those three curves are flat, you have built SkillOpt with extra machinery and must say so. If they bend, that is the result." A customer dashboard that can only ever go up is a vanity metric; these three can stay flat and that is reported as a null. Acceptance is governed by a gate that optimizes global compositional MDL/cost from the first commit (plan 015 §4) rather than a per-helper "does this one lift beat inline" objective, which is already falsified. And promotion is filtered by a computed process-reward stack (faithfulness, generality, parsimony, coverage, robustness) calibrated against a manufactured-gold selection split, with any dimension that fails to predict held-out correctness dropped (plan 015 §6). The curves measure whether the interface is earning its keep; the process stack stops it from "winning" by abstracting structure that does not track correctness.

The two-loop architecture, and why governance is the differentiated product

The system is two stacked optimizers over one locked control half (held-out gate, bounded edit budget, rejected-edit memory, fast/slow split, ported verbatim from SkillOpt and never re-tuned; plan 015 §1, plan 014 §3 mapping).

  • Loop A (tenant, fast). A per-tenant cycle proposes at most L bounded mutations to the tenant's grammar, gated on the tenant's own held-out split, with rejects sent to a shapeHash-keyed buffer the proposer never re-offers. Output: an updated lib/<tenant>/, staged for human adoption. The tenant's interface improves by being used. (plan 014 §6 Loop A.)
  • Loop B (provider, slow). A periodic reshape of the shared base abstractions by mining cross-tenant intentSignature clusters, accepted only if no regressed bucket grows for any tenant AND aggregate cross-tenant lifetime cost drops AND drift fingerprints still validate. Catastrophic-forgetting protection becomes catastrophic-cross-tenant-regression protection. This is explicitly future-work, gated behind ≥2 real tenants (and the one live governance run to date inverted — the gate fired 0/22, which is itself why it is future-work, not a green light) (plan 014 §6 Loop B, P5).

The reason this architecture matters is the most important honest concession in the design: against a frontier model, single-session correctness is roughly neutral (plan 014 §1, §11). If the pitch were "the agent answers better," there would be no product, because the frontier model already answers about as well inline. The differentiated product is governance and auditability:

  • Verifier-gated, not usage-gated promotion. A procedure is promoted because it passes an executed, oracle-free replay plus a paired cost-win plus non-regression where an oracle exists, never merely because it was called N times (plan 014 §5). This is the one place the system is strictly past SkillOpt: code can be validated by deterministic execution (model-independent), whereas prose can only be validated by the model re-reading it (circular, oracle-bound) (plan 014 §11). The gate's job is to correctly reject confidently-wrong or more-expensive helpers and promote only equally-correct-cheaper ones, which is precisely what ratifies our own falsification rather than papering over it.
  • Decline-under-drift beats confident-stale. Each procedure carries a @source-hash drift fingerprint; under detected drift the committed answer is no longer a valid fixed point, so the system forces re-derive-or-decline (plan 014 §5 fix b). On a truthfulness-graded score with a hallucination penalty (CRAG's −1 grader), a governed library that declines under drift strictly beats an ungoverned clone that confidently returns a stale, wrong answer (plan 014 §1, P4 headline). Governance-under-staleness, not raw correctness, is where reward > 0 is reachable.

So the product is an auditable, self-distilling evidence layer over a dataset: every promotion is gated, replayable, and lineage-backed; every refusal under drift is a feature; and the whole library tends toward fewer, deeper, better-tested procedures over time.

Who it is for and why now

This is for teams who put a frozen agent in front of a proprietary, drifting dataset and need the interface to that data to be governed, not vibes. Three things make it timely. First, frontier single-session correctness has saturated, so the marginal product is no longer "a smarter answer" but "an auditable, cheaper-at-depth, drift-aware path to the answer," and that is exactly what the two-loop gate produces. Second, the prevailing pattern (let the model accumulate skills/tools and reuse them) is the pile-of-shims failure mode we have a measured falsification for, so a system that compresses under a cost-aware gate is a concrete corrective, not a slogan. Third, datasets drift, and confident-stale answers are the expensive failure mode in production; a system whose default under drift is honest abstention, with the decline itself logged and gated, is the governance posture compliance-sensitive and high-stakes data teams actually need. The honest boundary of the offer: the win lands on serial-depth corpora and on governance-under-staleness, and the design says so in its own kill criteria rather than overselling amortisation everywhere.

Key takeaways
  • The product is a per-tenant procedure grammar that DISTILS (compresses under a cost-aware MDL gate) rather than ACCUMULATES thin shims a frontier model bypasses; distillation, not amortisation-everywhere, is the category.
  • "Improves the more you use it" is instrumented as three falsifiable distillation curves (description-length-per-intent down, compositional depth up, inline-rederivation rate down) with an explicit honesty clause: flat curves = SkillOpt-plus-machinery, reported as a null.
  • Two stacked loops over one locked control half: Loop A (fast, per-tenant, gated, staged for human adopt) and Loop B (slow, cross-tenant base reshape with a per-tenant no-regression veto, explicitly future-work behind 2+ tenants, with its one live run having inverted at 0/22).
  • Because single-session correctness is ~neutral against a frontier model, the differentiated product is GOVERNANCE: verifier-gated (executed oracle-free replay + paired cost-win), not usage-gated promotion, and decline-under-drift that beats confident-stale on a hallucination-penalized grader.
  • Value regime is honestly bounded to serial-DEPTH corpora (where deep composition is costly to inline) and governance-under-staleness; cost-amortisation on shallow fan-outs was falsified on our own k=5 PokeAPI run and the gate's job is to correctly REJECT that class.
  • For teams running a frozen agent over a proprietary, drifting dataset who need an auditable, lineage-backed, drift-aware data interface; timely because frontier correctness has saturated and confident-stale answers are the expensive production failure.

3Methodology

1. The frame: a frozen substrate and a trainable artifact over it

The method partitions the system into two strata that are never confused. The frozen substrate is the alphabet you never rewrite: the typed primitives df.db.* and df.compute.* exposed over a mounted dataset, together with the frozen agent that emits df.* code, the deterministic authoring cascade (src/observer/author.ts, authorFromSource.ts: promote top-of-main literals to typed params, rewrite df.answer to return, content-address by shapeHash + intentSignature), and the lineage capture that records every primitive call as typed I/O with scope/depth nesting and a replay-executable body. None of this is optimized. The trainable artifact is the per-tenant library of typed callable helpers the agent invokes (return await df.lib.someIntent(...)) via progressive disclosure (apropos / man / df.d.ts). This is the single substitution that makes the project a system delta rather than a reskin of SkillOpt: SkillOpt's trainable state is prose the agent reads; ours is typed code the agent runs (plan 014, sec 1–2). The consequence that earns the whole method is at the validation boundary — a prose skill is "validated" by the model re-reading it and completing a held-out task (the artifact is never executed; the signal is the model judging its own prose, circular and oracle-bound), whereas a typed callable is validated by running it on promoted literals and asserting answerEquals against the agent's prior committed answer: a deterministic, model-independent, oracle-free signal prose categorically cannot produce because prose has no execution semantics (plan 014, sec 2, anchor quarantineValidator.ts:326/338).

In plan 015 the trainable artifact changes class again: from a flat set of helpers to a compositional typed procedure grammar G where procedures compose procedures over the same frozen alphabet (df.db.* / df.compute.* / other learned procedures), each member carrying a typed signature, a deterministic skeleton, holes parameterizing the LLM-leaf judgments, and a co-emitted process-verifier contract (plan 015, sec 0, sec 2). The substrate is identical; only the object you train over it differs.

2. The locked control half (inherited from SkillOpt via plan 014)

We inherit that stance rather than relitigate it, and spend the novelty budget only on synthesis and the gate (plan 015, sec 0, sec 1). 3. The headline rule and the two forks

Object class picks the optimizer. A prose object takes reflection; a program object takes induction. Running reflection on a typed call-graph is editing a program with a prose tool, and it bottoms out at thin shims by construction, not by tuning (plan 015, sec 0). This single rule generates the fork:

  • Fork 014 (CodeOpt) — flat set + reflection. The trainable object is a flat library of df.lib.* helpers; the optimizer is SkillOpt's reflection optimizer re-targeted to emit executable code: the optimizer-LLM reads structured df.* call lineage plus the rejected-shape buffer and proposes the next library mutation (emit / merge / split / widen-params / deepen-body / demote / delete), emitted as code through the deterministic authoring cascade (plan 014, sec 3, sec 8). Honesty constraint folded in from the adversarial panel: this is not "a learning algorithm" — it is reflection re-targeted to emit code under a cost-aware executed gate; novelty is claimed at the gate and the second (retrieval/governance) optimizer, never at optimizer-as-reflection (plan 014, sec 8).
  • Fork 015 (Procedure-Grammar Induction) — grammar + induction. The object is the compositional typed grammar G; the optimizer is structured library induction with three operations that replace 014's single-trajectory reflective lift (plan 015, sec 3): (1) anti-unify (least-general-generalization) over a same-intentSignature cluster of trajectories to a candidate parameterized procedure — the operation that turns k anecdotes into one procedure; (2) compress / select by MDL over the whole corpus — keep a candidate iff it lowers corpus description length (recurs across ≥ k trajectories, shortens future caller-programs), the MDL prior being the statement "raw usage is noise, signal compounds across uses"; (3) accept by the gate (sec 4). The LLM is proposer, never disposer: neural picks which clusters to anti-unify, names and types the holes, suggests splits/merges; symbolic compression plus the gate decide (plan 015, sec 3).

The two forks are decided by a pre-registered R-vs-C bake-off behind a depth floor (plan 015, sec 7) — they are forks of one locked control half, differing only in synthesis and object.

4. The gate's precise scalar

The local objective ("does this one lift beat inline") is already falsified, so 015's gate is not rebuilt on it. The acceptance signal is corpus description length as the proxy for expected cost across all future callers (plan 015, sec 4):

Key formula — global compositional gate (015) 
score(G) = Σ_{x ∈ corpus} cost(caller-program_x | G)  +  λ · |G|
           └──── data cost (cost-aware token + TURN units, 014 §4) ────┘   └ library cost ┘

ACCEPT a mutation iff:
        score(G_{t+1}) < score(G_t)            (strict)
   AND  process-reward stack passes             (anti-Goodhart, §6)
   AND  no anecdotal-verifier regression        (014 §5 stack)

The cost(caller-program_x | G) term is measured in the cost-aware token-and-TURN units of plan 014's lifetime-cost model — the falsified +66,521-token gap was a turn-count tax, and the only lever that moved cost ~3.5x was helper depth, not width (plan 014, sec 4), which is precisely why 015's compositional grammar is the only object with cost headroom (plan 015, sec 2). This is the single place the method is strictly past SkillOpt: SkillOpt's gate is whole-artifact validation and cannot see composition because its artifact does not compose; ours optimizes compositional cost rather than merely validating a monolith (plan 015, sec 4). The process-reward guardrails are mandatory — they stop compression from "winning" by abstracting structure that does not track correctness.

For the flat fork (014), the same accept logic is instantiated as the cost-aware reward over the held-out selection split, paired against the inline-rewrite adversary on the same questions, where the lifetime cost decomposes into build_cost / E[reuses] + per_call_cost + staleness_risk_penalty − inline_cost_saved (cost in token AND TURN units — the falsified +66,521 gap was a turn-count tax, 014 §4), with acceptance requiring reward > 0 strictly and a per-pair cost-win fraction ≥ 0.70 and mean paired ratio ≤ 0.70 (the R8 dual anti-gaming gate) and a non-inferiority floor Δquality ≥ −ε — we require non-regression, never a correctness lift (plan 014, sec 4). The contrast with SkillOpt is exact: SkillOpt's select_gate_score returns Δquality alone and accepts on Δquality > 0, so equally-correct-cheaper helpers are invisible to it and equally-correct-more-expensive helpers (the falsified arm4 class) would be promoted; our gate promotes the former and rejects the latter.

5. The fast/slow split (momentum)

The optimizer runs as two loops, mapping SkillOpt's fast per-step gate and epoch-wise slow update onto a library/grammar object (plan 014, sec 6; plan 015, sec 5):

  • Fast pass (Loop A, per-tenant). A nightly per-tenant cycle proposes ≤ L_t mutations via the synthesis operator (deterministic cascade in 014, anti-unify + MDL in 015), each gated by the sec 4 scalar on the tenant's held-out split, with rejects written to the shapeHash-keyed rejected-abstraction buffer. The fast pass proposes abstractions; output is an updated lib/<tenant>/ (014) or admitted grammar members (015), staged for human adopt.
  • Slow pass (Loop B / refactoring pass, momentum). At each corpus boundary, one gated consolidation pass consolidates depth under its own conservative (L_t, Δ_t) and its own rejected buffer: it merges same-intent / different-shape procedures into one parameterized procedure (the cure for the silent-wrong-sibling landmine), splits a procedure whose intent-signature spans families when a sibling regresses, raises abstraction level by rewriting top-level procedures to call newly-admitted sub-procedures, and retires procedures the corpus stopped calling — every move through the same gate (plan 015, sec 5). In 014 the slow loop is made cross-tenant (reshape the shared lib/__seed__/ base abstractions by mining cross-tenant intentSignature clusters), accepted only if no regressed bucket grows for any tenant and aggregate cross-tenant lifetime cost drops; catastrophic-forgetting protection becomes catastrophic-cross-tenant-regression protection (plan 014, sec 6). Without the slow pass the optimizer is under-built — it is SkillOpt's momentum term, not an optional hint.
Key takeaways
  • The system is partitioned into a frozen substrate (df.db.*/df.compute.* — the alphabet you never rewrite, plus the frozen agent, authoring cascade, and lineage capture) and a trainable artifact (014: a flat library of invoked df.lib.* helpers; 015: a compositional typed procedure grammar G). The load-bearing consequence is at validation: prose is validated by the model re-reading it (circular, oracle-bound), code by deterministic execution (oracle-free, model-independent).
  • Both forks share ONE locked control half ported verbatim from SkillOpt and never re-tuned: count L_t (4→2 cosine), the NEW trust-region Δ_t for the program object (max ΔDL, ≤1 abstraction-level raised/op — keeps revisions near G_t so the rejected buffer and proposer retain learnable history), cosine schedule, gate-clamped autonomous LR (LLM proposes count, gate caps), insensitive rollout batch B, the intent-cluster minibatch, strict gate, shapeHash-keyed rejected buffer, refactoring slow-update momentum, and the fast/slow epoch.
  • The headline rule — object class picks the optimizer (prose→reflection, program→induction) — generates the fork: 014 = flat set + reflection re-targeted to emit code; 015 = grammar + structured induction (anti-unify a same-intentSignature cluster → MDL-select corpus-shortening abstractions → gate). Reflection on a typed call-graph yields thin shims by construction.
  • The gate optimizes a global compositional scalar score(G) = Σ_x cost(caller-program_x | G) + λ·|G|, accepting a mutation iff score strictly drops AND the computed process-reward stack passes AND no anecdotal-verifier regresses. This is strictly past SkillOpt, whose whole-artifact quality-only gate cannot see composition; cost is in token+TURN units because the falsified gap was a turn-count tax and only helper depth moved cost.
  • The fast/slow split is SkillOpt's momentum: a fast per-tenant pass proposes ≤L_t gated mutations with shapeHash-keyed rejects, and a slow refactoring pass at each corpus boundary consolidates depth (merge/split/raise-level/retire) through the same gate under its own conservative (L_t, Δ_t) and buffer — load-bearing per SkillOpt's ablations, not optional.

5Data Strategy: Corpus Inventory, Fitness Matrix, and the Hill-Climbing Data Plan

The learning layer adapts SkillOpt's text-space optimizer to a typed program object, and SkillOpt's most load-bearing structural fact is also its most overlooked: every one of its five benchmark evaluators is a deterministic per-task gold comparison (SearchQA SQuAD-EM, DocVQA ANLS, LiveMath MCQ, OfficeQA EM/F1, SpreadsheetBench cell-diff), and its splits are flat ID partitions — /tmp/SkillOpt/data/searchqa_id_split/split_manifest.json ships {train: 400, val: 200, test: 1400} as bare ID lists with the payload materialized from the source HF dataset. SkillOpt assumes the oracle and optimizes a prose skill.md against the held-out D_sel selection gate. Our fork keeps that locked control half (gate, bounded edit budget L_t, rejected-edit memory, fast/slow split) and changes only the object class and synthesis operator. That single decision reshapes the data requirement: a prose optimizer can climb on any oracle-bearing QA split, but a procedure-grammar optimizer (plan 015) can only climb where the corpus contains genuinely compositional serial depth — where ≥3 cross-intent sub-procedures recur and where re-deriving them inline is more expensive than calling a crystallised abstraction (br/16 Criterion-3). The entire data question therefore collapses to one screen: which of our corpora clears the depth floor as a value corpus, and which can only serve as a falsification control?

The empirical constraints are not opinions. The cost-amortisation thesis was falsified on shallow fan-outs: the valid k=5 PokeAPI run showed warm crystallised helpers cost more in every token unit and were less correct than inline re-derivation, and a quality-only gate would have promoted the losers. SkillCraft is saturated and cheap-to-inline: datafetch already reaches 94.4% pass on the full 126-task surface (eval/skillcraft/proof.md) at 3,027 effective tokens/task, but its 21 families are single-shape fan-outs that a frontier model re-derives inline at low token cost (br/16 Criterion-3 ranks symbolic/fan-out structure lowest-value). The only regime that has ever shown a positive depth signal is the OpenTraces dark-store family (+13.5pp), which is why plan 015 §7 names it as the candidate value corpus behind a pre-registered depth floor. 6Verifier Strategy: Constructed Oracle-Free Checks for the Oracle-Scarce Search Regime

The problem SkillOpt hides inside its benchmark choices

SkillOpt's entire optimizer discipline — bounded edit budget, rejected-edit buffer, slow update, and above all the held-out selection gate — rests on a precondition it never names: a per-task oracle. Every one of its five benchmark evaluators is a deterministic gold comparison. SearchQA is scored by SQuAD-EM against a gold string, DocVQA by ANLS against a gold transcription, LiveMath by MCQ-key match, OfficeQA by EM/F1 against gold fields, SpreadsheetBench by cell-diff against a gold workbook. In every case evaluate(answer) reduces to answer == gold (modulo a string metric). The gate's select_gate_score returns passrate(candidate) − passrate(current) and accepts on strict improvement, and that passrate is only definable because each held-out task carries its own gold.

This is fine for SkillOpt and fatal to lift directly. SkillOpt never verifies a search; it scores an answer against gold. It assumes the oracle and then does the genuinely hard work — aggregating the oracle's verdict over a held-out split to validate a general artifact. For real agentic search over a mounted, mutating dataset, the gold frequently does not exist: the question is open-ended, the corpus drifts under @source-hash fingerprints, the "right answer" is a defensible synthesis over evidence rather than a key in an answer file. Worse, our own falsification makes the missing oracle load-bearing rather than incidental: the valid k=5 PokeAPI run (commit 0665d5a27) showed warm crystallised helpers were more expensive in every token unit AND less correct than inline re-derivation, and a quality-only gate — exactly SkillOpt's gate — would have promoted those losers. So we cannot inherit the gate and swap in an LLM-judge for the missing gold: that re-introduces the circular, oracle-bound signal we are trying to escape (014 §2: prose "validation" is the model judging its own prose). We need a gate signal that is deterministic, model-independent, and oracle-free, and we need it to be denser than a sparse terminal gold so it can drive credit assignment where answer-gold is absent.

The reframe: don't build a search verifier, build a stack of per-search checks and aggregate

The move is structurally identical to SkillOpt's own shape, with one substitution. SkillOpt validates a general artifact by running per-task checks (the gold comparison) and taking the mean over a held-out split. We do exactly the same — general artifact, per-instance checks, mean over held-out — except SkillOpt receives its per-task check (gold is handed to every benchmark) and we CONSTRUCT it. We do not attempt a general "is this search correct" verifier; no such oracle-free function exists in the open-search regime. Instead we assemble a stack of anecdotal, per-search, oracle-free checks, each of which is individually weak and partial, and aggregate them. None is gold; together they constrain the answer space enough to gate.

Two anti-circularity disciplines govern the whole construction, inherited from 014 §5's verifier-panel patches:

  • Demote replay from oracle to determinism check. 014's executed replay (quarantineValidator.ts:326/338) re-runs a helper and asserts answerEquals against trajectory.answer.value. That expected value is a fixed point the agent already committed to, not gold. Treating it as gold is the circularity trap. So replay is a non-regression / determinism check — "running this helper still reproduces what the agent decided" — and we never promote on replay alone in the no-oracle regime.
  • Drift gates the fixed point. Under detected @source-hash drift the committed answer is no longer a valid fixed point (the live data moved). Drift is therefore a hard pre-replay gate (014 §5 fix b): on drift we skip idempotency and force re-derive-or-decline. This is precisely what stops a memorised stale clone from tautologically passing the determinism check.

The computed process-reward stack (computed, NOT judged)

The anecdotal stack above is a pass/fail gate on a finished answer. The process-reward stack is a dense, scalar reward over the procedure itself — it scores how the answer was produced, not just whether it survived. This is the 015 §6 stack, and its defining constraint is no LLM-judge appears anywhere in the reward. Every dimension is computed deterministically from lineage. A judge would re-import the circularity and the Goodhart surface we are spending the whole section to avoid.

The reward shape

The gate consumes a single scalar that fuses the answer-level stack, the process-level stack, and the lifetime cost from 014 §4:

reward(H) = λ_ans · answer_stack(H)
          + λ_proc · process_stack(H)
          − amortised_lifetime_cost(H)

answer_stack   = aggregate over the anecdotal per-search checks (faithfulness, cross-path,
                 invariants, coverage/abstention, replay-determinism), each run over k≥3 siblings
process_stack  = Σ over the computed dimensions (faithfulness, generality, parsimony,
                 coverage, robustness), weights calibrated on the manufactured-gold split
amortised_lifetime_cost = build_cost / E[reuses] + per_call_cost
                          + staleness_risk_penalty − inline_cost_saved        # 014 §4, in TURNS not just tokens

The process-reward term earns its place for three distinct reasons, and the third is why it is essential rather than merely nice:

  1. A better gate. It rejects procedures that reach a right answer by an untrustworthy path (low faithfulness, zero generality, crashes on the failure fixture) — confidently-wrong helpers the answer string alone would wave through. This is the 014 §4 falsification insurance expressed at the procedure level.
  2. A denser gradient (credit assignment). A terminal pass/fail gold gives the optimizer one bit per trajectory and no signal about which step was good. The process stack scores the procedure step-wise, so the reflection proposer (014) and the anti-unify/MDL inducer (015) get per-step credit — they learn which sub-procedure to keep, split, or retire, not just whether the whole thing passed.
  3. Essential in the low-oracle regime. Where answer-gold is sparse or absent, the answer stack is thin and noisy. The process stack densifies the signal precisely where the oracle is missing — it is computable on every trajectory regardless of whether a gold answer exists, because it scores the lineage, which always exists. This is the only way the gate has anything to optimize over an open-search corpus.

Anti-Goodhart guardrails

Constructed checks invite gaming; the manufactured reward is a Goodhart magnet. Four guardrails, each load-bearing:

  • Compute, don't judge. No LLM-judge in either stack. Every score is a deterministic function of lineage and execution. A judge is a soft target that the optimizer learns to flatter; a computed check is a hard constraint it must actually satisfy.
  • Checks must be CONSTRAINING. The universal test: remove the cited evidence and the answer must change. Faithfulness, coverage, and every process dimension are voided for any procedure where ablation leaves the output unmoved — that proves the citation/input was decorative. A check that nothing can fail is not a check.
  • Calibrate λ against the manufactured-gold split, and DROP dead dimensions. Weights λ_ans, λ_proc, and the per-dimension weights inside process_stack are fit on a held-out manufactured-gold selection split (a constructed corpus where we do know the right answer). Any dimension that does not predict held-out correctness on that split is dropped from the reward. A dimension that scores high on procedures the gold says are wrong is a Goodhart channel, not a verifier, and is removed — not down-weighted.
  • Genericity-over-siblings everywhere. Single-trajectory passes are inadmissible; every check runs over k ≥ 3 distribution-shifted siblings. This is the cheapest, strongest defence against memorisation-as-correctness.

How the verifier and process-reward feed the gate

The two stacks are not the gate; they are the gate's signal. The gate (014 §4 / 015 §4) consumes them in a fixed precedence so that a strong correctness signal can never be bought with cost savings, and a cost win can never be bought with an ungrounded answer.

A mutation is ACCEPTED iff, on the held-out selection split, paired against the inline-rewrite adversary by intent:

  1. Anecdotal stack passes with no regression — replay-determinism holds (drift-gated), faithfulness/cross-path/invariants/coverage all clear over k ≥ 3 siblings (014 §5: "no anecdotal-verifier regression"). A single hard failure here vetoes regardless of cost.
  2. Process-reward stack passes — every surviving (calibrated, non-dropped) dimension clears its threshold (015 §4/§6 anti-Goodhart filter). This stops compression or reflection from "winning" by abstracting structure that doesn't track correctness.
  3. reward(H) > 0 strictly — the fused scalar is positive after subtracting amortised lifetime cost, with the R8 dual cost-win (per-pair cost-win fraction ≥ 0.70 AND mean paired ratio ≤ 0.70) and the non-inferiority floor Δquality ≥ −ε.
  4. For 015 specifically, the same signals additionally gate the global compositional objective: score(G_{t+1}) < score(G_t) strict on corpus description length, conjoined with (1) and (2) above. The verifier stack is what keeps MDL compression honest — you may only shrink the grammar in ways that the anecdotal and process checks certify don't lose correctness.

This precedence is the whole point. Verification gates promotion (verifier-gated, not usage-gated — never "called N times"); the process reward both tightens that gate and supplies the dense gradient the synthesis loops train on; and the cost term sits underneath both, able to reject an equally-correct-more-expensive helper (the falsified arm4 class) but never able to rescue an ungrounded or non-generalising one. The construction is strictly past SkillOpt on exactly the axis SkillOpt assumed away: it gates a search with no gold by constructing, calibrating, and pruning the per-search checks itself.

Key takeaways
  • SkillOpt never verifies a search — all five of its evaluators are deterministic gold comparisons (SQuAD-EM, ANLS, MCQ, EM/F1, cell-diff); its gate's passrate is only definable because every held-out task carries gold. The open-search regime frequently has no such oracle.
  • The reframe keeps SkillOpt's exact shape (general artifact, per-instance checks, mean over held-out) but CONSTRUCTS the per-search checks instead of receiving them. No general search verifier is built; a stack of individually-weak oracle-free checks is aggregated.
  • The anecdotal verifier stack, ranked: evidence-grounded faithfulness (ablation-tested for circularity), cross-path agreement, emitted invariants/postconditions, coverage/abstention (the governance check, scored on CRAG's −1 grader), replay-determinism (the floor — a determinism check NOT an oracle, gated off under drift).
  • Replay is demoted from oracle to determinism check because the expected value is the agent's own committed fixed point, not gold; @source-hash drift is a hard pre-replay gate that forces re-derive-or-decline and stops stale clones passing tautologically.
  • The process-reward stack (faithfulness, generality over k≥3 siblings, parsimony, coverage, robustness) is COMPUTED from lineage, never LLM-judged — a judge would re-import the circularity and Goodhart surface the whole section avoids.

  • Anti-Goodhart guardrails: compute-don't-judge; checks must be CONSTRAINING (ablate the cited evidence and the answer must change); calibrate λ on the manufactured-gold split and DROP any dimension that doesn't predict held-out correctness (remove, not down-weight); enforce genericity over k≥3 distribution-shifted siblings everywhere.

The ordering is the safeguard. The structural pre-scan is a $0 gate that runs first and can abort the whole program before a single dollar of build or live-run spend is committed — which is also the honest surfacing mechanism for the "no compressible skeleton" risk: if the trajectories are mostly LLM-glue, the pre-scan finds nothing and the kill fires honestly, for free, before any synthesis is built.
